# Spec 011 验证 · 2026-11-07

> 2026-11-07 后续变更：用户要求移除沉浸模式，相关入口及逻辑已删除。下文的沉浸验收仅为历史记录；当前常规布局由 `WindowChromeLayoutTests` 覆盖。

在当前 Mac 上使用独立 Bundle ID 的原生测试副本验证；小说缓存复制到隔离书架，未改写正式书架。

- **I01 / I02**：从终端进入沉浸，⌘T 创建小说与行情页，⌘1 返回终端。三种内容均保留右上角退出入口，不显示窗口工具栏或页签；退出后完整工具栏、页签恢复。
- **I03**：终端会话切换后仍存在，Esc 不退出沉浸。小说没有独立模式按钮、菜单或快捷键；正文、目录及换章操作保持常规布局。界面截图：[终端](window-immersion/terminal.png)、[小说](window-immersion/novel.png)、[行情](window-immersion/stocks.png)。
- **I04**：120 × 90 pt 下，用 ⌘⇧I 退出，再右键顶部选择「沉浸模式」进入，点击右上角图标退出成功。退出按钮最终点击区域为 28 × 20 pt。
- **I05**：常规窗口实测锁定后原位解锁窗口出现。自动化补充验证：沉浸布局在锁定时恢复工具栏，解除锁定后恢复沉浸内容区域。
- **I06**：代码检查确认透明度恢复入口先退出沉浸。图标沿用已有悬停透明度机制；本轮未重复零透明度与跨应用焦点验收。

自动化通过 `MiniWindowChromeView` 公开内容展示和模式接口验证外观契约：相同内容视图切换模式后扩展、跨内容与多页签保持、退出恢复高度、最小尺寸退出按钮在窗内、锁定与解锁切换布局。先因缺少 `setImmersive` 接口编译失败，新增实现后通过。原有小说会话及行情测试一并运行，共 **5 项通过**；标准 Debug 构建通过。

模式按窗口保存于内存，不新增持久化。网页入口未做专项实机验证，本轮不扩大对全屏、多屏、其他系统版本的兼容性结论。

## 顶部零占位修正

- 先将公开窗口外观测试的内容高度从 340 改为 360 pt、顶部坐标从 20 改为 0，得到预期失败；实现后通过。终端保留原有 4 pt 内边距，不再保留窗口栏。最小窗口的终端高度由 62 增至 82 pt。
- 原生实测默认状态无工具栏、无退出图标占位；触碰右上角显示悬浮按钮，移入后点击恢复工具栏。普通移动到小说字号按钮可直接打开字号菜单，隐藏的悬浮按钮不拦截点击；自动化也验证隐藏时命中穿透。
- 原生 ⌥ 拖动由 (560, 200) 移至 (600, 230)，尺寸保持 280 × 360。使用直接移动避免系统 Option 拖动平铺。120 × 90 下悬浮退出仍可用：[小窗悬停](window-immersion/small-hover.png)。
- 下列截图已更新为零占位效果：终端、小说、行情。原有正文与行情控件属于内容本身，不因窗口沉浸而移除。
