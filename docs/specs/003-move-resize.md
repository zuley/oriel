# Spec 003：小窗拖动与边缘缩放

最新紧凑布局修订见[Spec 006](006-compact-layout.md)：默认280×360pt、工具栏与首页间距收紧；该规格覆盖本文旧默认尺寸/外观坐标，历史测试坐标及证据保留。

日期：2026-11-05。状态：本轮实施的 SDD 基线；用户已确认拖动和缩放可用，新增120 × 90下限和紧凑布局已取得本机原生证据。自动隐藏、锁定兼容及尚未覆盖的细分验收仍待验证，不因规格写入或构建成功而判为通过。

依据：用户要求小窗支持拖动与边缘缩放，以及本轮确定的尺寸、布局、锁定和自动隐藏规则。

同日修订：用户真实反馈“拖动和缩放可以用，但 280 × 400 最小太大，要缩到很小”。最低尺寸因此调整为 120 × 90 pt，并增加紧凑工具栏与图标空状态。280 × 400 是先前实现和验证的历史基线，不改写该阶段测得的尺寸；新下限经原生右下角缩放钳制验证，小尺寸及原有完整布局均取得渲染证据。具体覆盖范围见[验收记录](../verification/003-move-resize.md)。

关联：[Spec 001：单窗行为](001-single-window-behavior.md)、[Spec 002：参考图外观](002-reference-window-appearance.md)。本规格明确覆盖其中“固定位置、不提供拖拽或缩放”的旧范围限制。初始参考图外观、通用文案和已有窗口行为继续适用；M0 未完成的焦点、系统与资源验收不随本需求自动通过。

## Problem Statement

现有小窗固定在初始位置和尺寸，用户不能根据正在阅读的内容和桌面空间调整它。加入移动和缩放后，如果鼠标热区仍使用旧 frame，或自动隐藏在操作中途生效，会导致窗口消失、旧位置唤醒或无法完成调整。

用户需要直接调整真实窗口，同时保留网页选文、工具栏按钮、锁定穿透和菜单栏恢复的既有行为。初版 280 × 400 pt 下限仍占据过多空间，小窗需要进一步缩小，同时让必要控件保持可用。

## Solution

未锁定时，从工具栏空白区域拖动窗口，通过四边和四角执行 macOS 原生缩放。窗口内容随可用空间布局，实际 frame 同步到行为控制器。几何交互期间暂停自动隐藏判定；交互结束后按最终 frame 和当前指针立即确定显隐。

移动、缩放只改变位置和尺寸，不修改锁定、自动隐藏或透明度配置。锁定后除 [Spec 004](004-lock-recovery.md) 定义的原锁图标28 × 28 pt交互区域外，其余区域继续穿透；就地普通解锁或菜单栏恢复后再次允许操作，两种命令的自动隐藏语义分别保留。

最低支持 120 × 90 pt。空间不足时省略部分工具栏按钮和首页说明，仅保留可容纳的操作入口与居中小图标；网页保留小视口并继续滚动，不要求把网页内容缩放到全部可见。

## User Stories

1. 作为用户，我希望拖动工具栏空白处移动小窗，以便避开主应用的重要内容。
2. 作为用户，我希望点击工具栏按钮只执行对应命令，以免按钮操作误变成拖动。
3. 作为用户，我希望网页内容仍能选文和滚动，以便在调整窗口后继续浏览。
4. 作为用户，我希望从四边和四角缩放窗口，以便根据内容调整阅读空间。
5. 作为用户，我希望窗口有合理的最小尺寸，以免主要内容和控件被裁切。
6. 作为用户，我希望放大或缩小后工具栏仍靠边排列，网页填满内容区，以便控件位置保持清晰。
7. 作为用户，我希望首页图文整体居中且字体不随窗口拉伸，以便保持参考图的视觉比例。
8. 作为用户，我希望正在拖动或缩放的窗口不会自动隐藏，以便连续完成一次操作。
9. 作为用户，我希望操作结束后立即按新位置判断显隐，以免窗口停留在错误的显示状态。
10. 作为用户，我希望移动后的边缘唤醒跟随新位置，以免旧位置继续触发窗口。
11. 作为用户，我希望锁定后不能意外移动或缩放小窗，同时仍可操作下层应用。
12. 作为用户，我希望恢复、收起、关闭和重新创建能够清理未完成的交互，以免旧回调改变新窗口或撤销管理命令。
13. 作为用户，我希望把窗口缩到 120 × 90 pt，以便在需要时只占用很小的屏幕区域。
14. 作为用户，我希望窄窗口中的管理操作仍能从应用菜单访问，以免缩小后失去管理入口。

## Implementation Decisions

### 尺寸与布局

| 项目 | 契约 |
| --- | --- |
| 初始尺寸 | 320 × 480 pt；若创建时所在屏幕的可见区域更小，分别以该区域的宽、高为上限 |
| 常规最小尺寸 | 120 × 90 pt，由原生窗口的最小尺寸约束执行；替代先前的 280 × 400 pt 下限 |
| 小屏最小尺寸 | 每个维度取“常规最小尺寸”和“实际初始尺寸”中的较小值，避免最小尺寸反而大于可容纳的初始窗口 |
| 拖动入口 | 仅未锁定窗口的工具栏空白区域；按钮命中区和网页内容区不作为拖动背景 |
| 缩放入口 | 使用带 `.resizable` 的原生 NSPanel，四边、四角使用扩大的缩放热区，已有按钮和终端滚动条优先接收点击和拖动 |
| 内容区 | 随窗口尺寸填充，保持原有外边距；WKWebView 随内容区调整宽高 |
| 常规工具栏 | 宽度≥280pt：关闭/收起在左，后退/前进随后；眼睛/设置/锁在右 |
| 紧凑工具栏 | 宽度<280pt：保留关闭、收起、设置、锁；关闭/收起中心x=20/40，设置/锁中心x=宽度−56/−20；设置仅调整两项透明度；边缘唤醒仍可从系统菜单栏访问 |
| 常规首页 | 可用内容宽度 ≥ 264 pt 且高度 ≥ 352 pt 时，保持图标、文案、分隔线和三项内容提示的内部比例与字号，并在内容区整体居中；280 × 400 及以上的正常布局保持原样 |
| 紧凑首页 | 可用内容宽度 < 264 pt 或高度 < 352 pt 时，仅显示居中的小窗口加号图标，隐藏主标题、副标题、分隔线和三项内容提示；图标适应剩余空间，不以裁切说明文字替代紧凑布局 |
| 最小布局 | 120×90pt下关闭、收起、设置、锁不重叠，图标空状态完整；网页保留小视口 |

320 × 480 pt 是默认外观基线，不是固定内容画布。缩放时不能只改变窗口外框而让内部保持旧尺寸。工具栏断点依据窗口宽度，首页断点依据扣除工具栏和边距后的可用内容尺寸，两者分别判断；例如宽而矮的窗口可以保留完整工具栏，同时使用紧凑首页。恢复到足够大的尺寸时，隐藏的按钮和首页说明重新出现，原有字号不变。屏幕极小、迫使初始尺寸低于常规最小尺寸的情况应单独记录可用空间和布局结果，不能把常规最小尺寸的验收扩展为未经测试的任意屏幕尺寸保证。

### 真实 frame 与原生事件

- 使用 AppKit 全局屏幕坐标和 pt，同一坐标系下传递真实 `NSWindow.frame` 与全局指针位置，不把参考图阴影边距或 Retina 物理像素计入热区。
- 原生窗口的 `didMove`、`didResize` 回调负责把当前真实 frame 同步给行为控制器；不能仅记录鼠标位移猜测窗口最终位置，也不能只在鼠标松开时更新。
- `performDrag(with:)` 接收启动拖动的原始鼠标按下事件。Apple 明确说明该调用会立即返回，而且调用方可能收不到 mouse-up，因此不能将调用返回或视图的 `mouseUp` 作为唯一结束信号。[Apple：performDrag(with:)](https://developer.apple.com/documentation/appkit/nswindow/performdrag(with:))
- 拖动结束采用仅在拖动期间启用的鼠标按键状态观察；左键释放后读取最终 frame 和指针，再结束本次几何交互。观察必须能在恢复、收起、关闭和销毁时停止，不引入常驻的额外轮询。
- 自定义热区使用按下和松开界定缩放，系统发起的缩放沿用原生 live-resize 回调；结束前再次同步最终 frame。拖动观察、resize 回调和 frame 回调都绑定本次窗口 ID。
- `.resizable` 和 delegate 接线属于实现选择，不能替代四边、四角的真实操作验收；边框点击被内容视图吞掉时必须修复接线，不能据此缩减支持方向。

### 控制器公开边界

沿用已确认的“窗口行为控制器与公开 snapshot”测试边界，新增以下公开操作：

| 操作 | 可观察契约 |
| --- | --- |
| `updateFrame(_:for:)` | 对当前存活窗口的匹配 ID 更新 snapshot.frame，保留显隐和各项配置；frame 实际改变时清空此前指针轨迹历史 |
| `beginGeometryChange(for:)` | 为当前窗口开始几何交互；交互期间普通指针采样不改变显隐，不建立可用于事后跨边缘唤醒的历史 |
| `endGeometryChange(pointer:for:)` | 仅结束当前有效的几何交互；自动隐藏开启时按最终 frame 的外扩 12 pt 保持区立即判定显隐，关闭时保持显示；不改变锁定、自动隐藏和透明度配置 |

旧窗口 ID、已关闭窗口的回调均为无操作，不能修改新窗口的 frame、显隐或采样历史。应用适配层在锁定时禁止启动用户拖动和缩放；更新真实 frame 本身不等于授权一项用户交互。

### 几何交互与自动隐藏

1. 开始操作时先进入几何交互状态，再交给原生拖动或 live-resize，避免第一帧移动后被普通显隐采样隐藏。
2. 操作中持续接收真实 frame 更新，但暂停自动隐藏的显隐判定；暂停判定不改变用户的自动隐藏开关。
3. 操作结束时先应用最终 frame，再按当时的全局指针判定：位于窗口或其外扩 12 pt 闭合保持区内则显示；自动隐藏开启且位于区外则隐藏。
4. 操作结束后恢复既有边缘唤醒规则；热区以新 frame 为准，旧位置不再有独立的唤醒作用。无历史首次中央不唤醒、相邻实际采样由外到内补发唤醒等规则继续适用。
5. `updateFrame` 对真实几何变化清空轨迹历史，避免将旧坐标下的前一次采样与新坐标下的采样拼成错误的跨边缘进入。
6. 恢复、收起、关闭均清理几何交互及其观察资源，并执行原命令的完整状态转换。随后迟到的结束回调不能撤销恢复、重新显示已收起窗口或影响重建后的新窗口。没有有效交互时的结束回调不重新决定显隐。

用于测试的固定例子：旧 frame 为 `(100,100,320,480)`，新 frame 为 `(600,200,400,500)`。新保持区边界为 x ∈ `[588,1012]`、y ∈ `[188,712]`；旧边缘点 `(95,150)` 不再唤醒，新边缘点 `(595,250)` 可以唤醒。操作结束时 `(650,250)` 位于新保持区内，应显示；`(580,250)` 位于区外，自动隐藏开启时应隐藏。预期来自这些独立给定的几何例子，不在断言中复制实现算法。

### 锁定与恢复

- 锁定时，除 [Spec 004](004-lock-recovery.md) 的就地取消按钮矩形外，窗口、工具栏和边框继续鼠标穿透，点击或拖动边缘不能移动、缩放窗口；下层应用仍可接收相应输入。取消按钮仅用于解锁，不作为拖动或缩放入口。
- 几何调整不自动解锁，不改变透明度，也不自动关闭边缘唤醒。
- 菜单栏“显示并解锁”保留现有语义：显示、解除锁定、关闭自动隐藏，并取消尚存的几何交互；此后工具栏拖动和边缘缩放可用。
- 收起和关闭保留各自既有语义，不通过补发几何交互结束事件恢复显示。

## Testing Decisions

### TDD

自动化只通过控制器公开操作与 snapshot 验证行为，不断言私有 gesture 字段、Timer 实例或回调调用次数。采用一条失败行为测试、一份最小实现的顺序推进，不一次性铺开全部实现。

首条切片可验证更新 frame 后旧热区不再唤醒、新热区可以唤醒且配置保持；后续逐条覆盖几何变化清空历史、交互期间不隐藏、结束后区内/区外即时判定、自动隐藏关闭时保持显示，以及恢复、收起、关闭和旧 ID 的隔离。已有锁定、快速跨边缘唤醒与收起测试继续回归。

原生最小尺寸约束、鼠标命中、窗口实际坐标变化和布局效果属于适配及实机验收，不能由控制器单元测试代替。

## Further Notes

- 原生拖动返回时机依据 Apple API 文档及本机 AppKit SDK 的 `NSWindow` 头文件注释核对；其“立即返回、可能没有 mouse-up”语义是结束检测设计的依据，不是实机行为已经通过的结论。
- frame 同步避免反向循环：原生 delegate 报告真实 frame，控制器接收几何结果；不要因 snapshot 更新再无条件重设相同 frame，制造重复回调或抖动。
- 工具栏拖动命中与系统边缘缩放可能相邻，必须在真实鼠标操作中核对；内容区不应覆盖或吞掉原生边缘输入。
- 动作生命周期与窗口 ID 分开核对：仅验证“旧 ID 不生效”不足以防止同一窗口在恢复或收起后被迟到的结束回调重新显现。

2026-11-06 复核：创建、移动、缩放和结束拖动时，以圆角窗体的屏幕坐标更新唤醒热区。4 pt 投影位于窗体之外。在可见窗体外 12 pt 命中，13 pt 和 16 pt 均在热区外。对 120–290 pt 的窗口逐点检查，顶部各按钮可独立命中，至少留有 14 pt 连续拖动空白。

2026-11-06 扩大缩放热区：按窗口外框计，左右和下边的热区宽 14 pt，顶边高 12 pt。上方两角各为 20 × 12 pt，下方两角各为 20 × 20 pt。工具栏两侧让出图标的点击位置。拖动固定对边或对角，以初始按下点计算大小；最小尺寸仍为 120 × 90 pt。通过系统鼠标事件验证了四边、四角、最小尺寸限制，以及最小窗口的标题栏拖动和新建页签。

缩放光标跟随实际热区，悬停即可显示，无需先点击激活小窗。左右边使用水平双箭头，上下边使用垂直双箭头，四角按对角线方向显示。非激活小窗悬停时临时启用 WindowServer 的未公开连接属性 SetsCursorInBackground，移出、隐藏、锁定或关闭时解除。在 macOS 26.6.2 上已比对八个热区的系统光标图像，并验证移出、锁定和关闭时恢复。其他系统版本待实测；连接属性不可用时回退至 AppKit 光标机制。
