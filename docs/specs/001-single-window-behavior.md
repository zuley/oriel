# Spec 001：单窗锁定与边缘唤醒

## Problem Statement

开发者、设计师和写作者需要在工作时持续参考非视频信息，同时继续操作主应用。悬浮内容不能长期遮挡操作，也不能在锁定、隐藏后失去恢复入口。

原设计将关键能力“锁定穿透与移入显隐共存”放在 M4。它与焦点、全屏 Space 和鼠标检测相互影响，应先用一个真实小窗验证，再扩展多窗管理。

本规格回答：一个自承载内容的小窗，能否完成“锁定 → 自动隐藏 → 边缘唤醒 → 保持穿透 → 从菜单栏恢复操作 → 关闭”的完整流程。

## Solution

增加一个先于原 M1–M4 的 M0 验证阶段：菜单栏入口、一个 NSPanel、一个固定的本地测试网页、最少的管理命令。先验证窗口行为，不依赖外部站点登录、网络或页面变化。

### 已确认的方向

- 沿用原设计：macOS 14+，菜单栏常驻，自承载内容，不做其他应用画面镜像。
- 沿用原设计：Swift、AppKit NSPanel、SwiftUI、WKWebView；窗口能力与内容渲染分离。
- 沿用原设计：锁定时鼠标穿透，菜单栏提供恢复入口；锁定和自动显隐可以共存。
- 用户本轮确认：首版支持链接、滚动和选文，表单输入暂缓。
- 用户本轮确认：触碰边缘才显示；显示后进入窗口内部仍保持显示。

### 已确认的 M0 范围

- M0 的网页能力仅承载一个固定测试网页，包含链接、可滚动内容和可选择文本。根据后续 [Spec 002](002-reference-window-appearance.md)，新建默认显示参考图首页，测试网页从调整菜单进入。
- 同时最多一个小窗，初始尺寸根据用户参考图调整为 320 × 480 pt（初版为 320 × 240 pt）。后续用户要求拖动与边缘缩放，现由 [Spec 003](003-move-resize.md) 定义。存在窗口时不可重复创建；关闭后可以重新创建。
- M0 只采用完全隐藏与显示两种视觉结果，不同时实现淡入淡出。
- 菜单栏提供“显示并解锁”恢复命令：显示窗口、解除锁定、关闭自动隐藏。这是故障恢复路径，不能依赖小窗自身收到鼠标事件。
- 关闭表示移除窗口；自动隐藏仅改变可见性。关闭后不得因鼠标经过旧位置再次出现。
- M0 暂不增加独立的“手动隐藏但保留窗口”命令，避免与自动隐藏混淆。

## User Stories

1. 作为需要参考信息的用户，我希望从菜单栏创建一个小窗，以便在主应用旁查看内容。
2. 作为用户，我希望小窗支持链接、滚动和文本选择，以便完成基本浏览。
3. 作为用户，我希望锁定小窗后，取消穿透按钮以外区域的点击和滚动能到达下面的应用，以便继续操作主应用；例外范围见 [Spec 004](004-lock-recovery.md)。
4. 作为用户，我希望自动隐藏与锁定同时生效，以便需要时查看内容，其余时间减少遮挡。
5. 作为用户，我希望触碰隐藏窗口的边缘后显示内容，以便通过固定位置找回它。
6. 作为用户，我希望鼠标从边缘移入内容内部后窗口保持显示，以便阅读和浏览。
7. 作为用户，我希望鼠标离开保持显示区域后窗口隐藏，以便腾出视野。
8. 作为用户，我希望从菜单栏显示并解锁小窗，以便随时恢复操作。
9. 作为用户，我希望关闭的小窗不再被鼠标唤醒，以便关闭操作具有确定结果。
10. 作为用户，我希望重新显示不会改变我设定的透明度，以便保持阅读偏好。

## Implementation Decisions

### 行为状态与规则

以下是已确认的行为契约；规格确认不等同于实现或验收通过：

| 条件或操作 | 期望结果 |
| --- | --- |
| 创建窗口 | 可见、未锁定、未开启自动隐藏 |
| 已有窗口时再次创建 | 不增加窗口、不重置已有窗口的状态 |
| 开启或关闭锁定 | 仅改变鼠标穿透状态，保持当前可见性和自动隐藏配置 |
| 开启自动隐藏，鼠标位于保持显示区域外 | 隐藏，保留窗口及其位置 |
| 开启自动隐藏，鼠标位于保持显示区域内 | 保持显示 |
| 已自动隐藏，采样位置命中边缘唤醒区 | 显示，保留锁定与透明度配置 |
| 已自动隐藏，上一次有效实际采样在保持区外，本次实际采样进入保持区 | 视为跨边缘进入并显示，即使本次已落在中央；保留锁定与透明度配置 |
| 已自动隐藏，没有有效采样历史，首次实际采样落在中央非热区 | 保持隐藏；首次中央位置本身不构成唤醒条件 |
| 已自动隐藏，前后两次实际采样均在保持区外 | 保持隐藏，即使连接两点的线段穿过窗口 |
| 已显示，鼠标进入内部或仍位于边缘区域 | 保持显示 |
| 已显示且开启自动隐藏，鼠标离开保持显示区域 | 隐藏 |
| 开启或关闭自动隐藏 | 按上述规则立即判定显隐，并清空连续采样历史；该操作的当前指针位置不作为采样历史 |
| 关闭自动隐藏 | 恢复显示，保留锁定状态 |
| 显示并解锁 | 显示、解除锁定、关闭自动隐藏，并清空采样历史 |
| 收起到菜单栏（Spec 002 的减号） | 隐藏并关闭自动隐藏、清空采样历史，保留窗口和锁定/透明度；随后指针采样不唤醒，通过菜单栏恢复 |
| 关闭 | 从受管理窗口中移除并清空采样历史，此后指针采样不再影响该窗口 |

锁定、自动隐藏配置、当前可见性和窗口生命周期应分别建模。不能仅用窗口当前是否可见来推断用户意图。

### 热区几何与采样

原文描述边缘窄条，但示例代码检查的是包含整个窗口的外扩矩形。实现时必须分别定义“唤醒区”和“保持显示区”。

以窗口边界为中心，在内外两侧各取 12 pt 构成边缘带。保持显示区为整个窗口及外扩 12 pt 的闭合矩形，四边及四角均包含；唤醒区等于该闭合矩形减去窗口内缩 12 pt 后的严格内部。内缩矩形的边界仍属于唤醒区。距离使用屏幕坐标中的 pt，不使用显示器物理像素。M0 不提供热区宽度配置。

固定验收例：窗口左下角为 (100, 100)，宽 320、高 240；保持区为 x ∈ [88, 432]、y ∈ [88, 352]，中央非热区为 x ∈ (112, 408)、y ∈ (112, 328)。该坐标是测试材料，不规定应用启动位置。

- (95, 150) 位于左侧外缘，应能唤醒。
- (105, 150) 位于左侧内缘，应能唤醒。
- (150, 150) 位于中央：隐藏且无有效历史时不单独触发唤醒，已显示时保持显示。
- (80, 150) 位于保持显示区外，开启自动隐藏时应隐藏。
- (88, 88)、(432, 352)、(112, 150)、(408, 150) 均位于唤醒区边界，应能唤醒。
- (87, 150) 和 (433, 150) 位于保持显示区外。
- 隐藏时，同一窗口连续收到实际采样 (80, 150) → (150, 150)，第二次采样应补发跨边缘唤醒。
- 隐藏时，实际采样 (80, 150) → (450, 150) 两端均在保持区外，不显示，尽管两点间线段穿过窗口。
- 开启自动隐藏时传入 (80, 150)，随后首次实际采样为 (150, 150)，应保持隐藏：开关操作的位置不是历史采样。
- 关闭重建、恢复或自动隐藏切换后，重新开启自动隐藏并以区外当前位置进入隐藏状态；随后首次中央实际采样不唤醒。旧窗口 ID 的采样不得改变新窗口状态或建立历史。

记录同一个存活窗口、自动隐藏开启期间的上一次有效实际 `samplePointer` 位置。直接命中热区照常唤醒；隐藏时，只有“上一次实际采样在保持区外、本次在保持区内”才补发跨边缘唤醒。该规则使用相邻采样点的区域变化，不做完整轨迹插值；两端均在区域外时不推断中途穿过。

新窗口创建、关闭、恢复及自动隐藏开关清空历史；已有窗口时重复创建不重置状态或历史。开关操作接收的当前指针仅用于立即显隐判定，不参与连续采样历史；自动隐藏关闭时的采样、旧窗口 ID 的采样均不得建立或污染历史。拖动、缩放期间的显隐及 frame 同步现由 [Spec 003](003-move-resize.md) 补充。

### 内容与焦点

- “浏览为主”意味着本轮不承诺表单输入兼容性，不意味着可以通过禁止全部交互来实现。
- 不激活所属应用、是否成为 key window、键盘输入去向分别验证。文本选择等操作所需的具体焦点行为通过真实网页确认。
- 自动唤醒不得激活 Oriel 或改变主应用的键盘焦点；锁定期间除 [Spec 004](004-lock-recovery.md) 的就地取消按钮外，交互继续到达下层应用。未锁定时链接、滚动、选文的 key window 行为允许实测后细化，但不能以无法浏览作为低干扰的实现代价。
- 链接验收先覆盖测试网页内的普通链接；新窗口链接、外部协议、登录和复杂站点兼容性在完整网页功能规格中定义。
- 内容隐藏不代表所有网页任务已暂停；不得把媒体暂停 API 当作 JavaScript 和网络轮询的通用冻结方案。

### 实现边界

- 窗口行为控制负责接收管理命令、配置变化、指针采样并产生公开可观察状态。
- AppKit 适配负责把行为结果作用于真实窗口；鼠标采样来源独立于窗口自己的鼠标事件。
- 指针输入与时间来源应允许确定性替换，自动化测试不依赖真实鼠标位置或实际等待 30 ms。
- M0 保持 30 ms 采样间隔，响应与资源开销仍需测量；该间隔不是“开销可忽略”的证据。
- 仅在受管理窗口存在且开启自动隐藏时运行指针采样；关闭自动隐藏、关闭窗口或退出应用后停止。关闭后到达的采样不能使已移除的窗口复活。
- 先建立这条切片需要的模块，不提前实现完整内容类型、Pro 扩展或插件结构。
- 实施时为键盘和辅助访问补充标准“小窗”应用菜单，与状态栏复用同一组命令；不引入全局快捷键或另一套管理状态。

## Testing Decisions

### 已确认的唯一自动化测试边界

**窗口行为控制器与公开 snapshot**：通过创建、锁定、设置自动隐藏、输入指针位置、显示并解锁、关闭等公开操作，读取 snapshot 中窗口是否存在、是否显示、是否锁定等公开结果。

用户已确认该测试边界。每条行为采用一轮失败测试与最小实现；新增行为前复用已有公共操作建立前置条件，不直接修改内部状态。

测试验证业务行为，不验证内部字段布局、私有方法或内部调用次数。几何预期来自本规格的固定例子，不在断言中复刻实现公式。

### 第一条 TDD 切片

**给定**一个已锁定、开启自动隐藏且当前隐藏的小窗，**当**输入命中边缘热区的指针位置，**那么**窗口应显示且仍保持锁定。

先运行这条测试并确认因缺少行为实现而失败，再写使其通过的最小实现。随后按反馈逐条增加“移入内部保持显示”“移出隐藏”“恢复操作”“关闭不复活”等行为，不一次性铺开全部测试。

每条行为保留规格条目与测试对应关系；通过后进行审阅和必要整理。行为需求改变时同步修改规格与验收依据。

本次修订增加一条先失败后实现的用例：隐藏且锁定的小窗依次收到区域外、中央的实际采样，第二次应显示且保持锁定与透明度。随后逐条验证无历史首次中央不唤醒、两端在外不唤醒、旧窗口 ID 隔离，以及关闭、恢复、自动隐藏切换后的历史清理。自动化通过后仍须复测用户报告的实际漏触发，不能据此直接宣布唤醒稳定性通过。

## Further Notes

### 阅读原设计后需修正的技术假设

1. **非激活面板不等于无法键盘输入。** Apple 对 `nonactivatingPanel` 的定义是不激活所属应用；`becomesKeyOnlyIfNeeded` 文档进一步说明非激活面板如何按命中视图的需要取得键盘焦点。表单暂缓是本轮用户选择的范围，不应归因于绝对技术限制。[nonactivatingPanel](https://developer.apple.com/documentation/appkit/nswindow/stylemask-swift.struct/nonactivatingpanel)、[becomesKeyOnlyIfNeeded](https://developer.apple.com/documentation/appkit/nspanel/becomeskeyonlyifneeded)
2. **暂停媒体不等于暂停全部网页任务。** Apple 对 `setAllMediaPlaybackSuspended` 的承诺是媒体播放挂起；因此不能据此声称已暂停任意网页的定时器、请求和动画。[Apple API 文档](https://developer.apple.com/documentation/webkit/wkwebview/setallmediaplaybacksuspended(_:completionhandler:))
3. **全屏可见性需要验证。** Apple 对 `fullScreenAuxiliary` 的描述是能与全屏窗口显示在同一 Space，不足以单独证明该窗口始终压在任意应用之上。[Apple API 文档](https://developer.apple.com/documentation/appkit/nswindow/collectionbehavior-swift.struct/fullscreenauxiliary)
4. 原文关于竞争空白、内存固定数值、商标/域名可用性和市场转化的结论未在本轮验证，不作为工程验收依据。

### 后续推进顺序建议

1. **M0：单窗行为验证。** 完成本规格中的行为闭环与实机证据；发现不满足要求的系统行为时先修正规格或技术方案。
2. **M1：一个真实网页窗。** 输入 URL、加载/失败反馈、基本浏览、移动和关闭。
3. **M2：多窗与基础恢复。** 增删改、重启恢复、无效屏幕与位置校正；基础恢复与付费场景快照分开。
4. **M3：发布前的窗口体验。** 透明度、缩放和已确认的置顶行为；明确全局快捷键是否为首版发布门槛，消除原文 P0 与 M5 的冲突。
5. **后续独立规格。** 原生内容、文件、吸附、模板、URL Scheme 和商业化逐项进入。
