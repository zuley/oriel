# Spec 005：背景与内容透明度

日期：2026-11-05。按用户最新要求，将“文字透明度”改为“内容透明度”，作用于整个内容区，而非仅文字。

## 当前契约

- 设置浮层从上到下排列「内容透明度」「背景透明度」，只显示标签与连续滑杆。左端完全透明，右端完全清晰。新建小窗默认内容与背景均为 25% 透明，两条滑杆均位于距左端 75% 处。
- 背景透明度控制窗体底色、内容卡片底色以及顶部所有图标按钮，包括独立锁图标命中面板。锁定时仅恢复子面板绘制锁图标，主窗口不重复绘制该图标；子面板没有额外白底，解锁后由主窗口恢复绘制。
- 内容透明度统一作用于内容容器：文字、插画、内容图标、装饰线、卡片及所承载的WebView整体。容器alpha统一合成，不分别改字色。
- 卡片作为内容的一部分，其底色同时受背景透明度和内容透明度影响；背景不再单独控制内容图标与插画。
- 设置浮层与操作提示保持可见，不跟随上述滑杆变透明。内容调为100%时，顶部按钮和窗体底色不受影响。
- 同一小窗关闭再打开设置、拖动缩放、锁定解锁保留数值；关闭重建或退出后恢复默认。本轮不增加持久化。
- 设置展开期间暂停自动隐藏指针判定；浮层关闭后恢复。窗口隐藏、锁定、关闭时关闭浮层。
- 设置中不放导航、恢复或其他窗口操作。此变更不意味着任意网页底色和元素可以分别处理；WebView仅随内容容器整体透明。

## 当前验证

- 标准Xcode构建通过，未修改Core。
- 原生设置名称为背景透明度、内容透明度。
- 通过真实设置滑杆将内容设为100%，整个内容区消失，背景/顶部按钮/设置浮层仍可见；再调到50%，文字、插画、图标与装饰同步变淡。
- 原生视图渲染对照：背景不透明而内容完全透明时，只剩底色和工具栏；背景完全透明而内容不透明时，内容区保留，顶部按钮不可见。
- 以前原生设置的数值保留及小尺寸检查作为历史证据保留；本次未单独扩大为网页、自动显隐、焦点或全屏回归通过。

## 修订历史

最初只调整文字，随后图标随背景透明度变化；上述旧分组现由“背景/顶部按钮”和“整个内容区”两组契约替代。旧渲染或旧验收不能当作当前分组的预期。
