# Spec 004：锁定后的就地取消穿透

日期：2026-11-05。状态：修复规格基线；已取得修复前系统命中的正负对照，修复后两种尺寸的命中与取消动作、解锁后关闭、重建及锁定状态退出已验证。自动显隐、焦点、全屏及未覆盖的生命周期路径仍待验证，详见配套验收记录；不宣称完整M0通过。

依据：用户反馈开启锁定后，小窗自身的开关也会穿透，无法在原位置取消。配套[验收记录](../verification/004-lock-recovery.md)。本规格修订 [Spec 001](001-single-window-behavior.md)、[Spec 002](002-reference-window-appearance.md)、[Spec 003](003-move-resize.md) 的全窗穿透表述：锁定且可见时，只有下述取消按钮矩形接收鼠标，其他区域仍穿透。

## Problem Statement

原实现将整个主面板设为忽略鼠标事件，工具栏中的锁定开关也随之失效。虽然菜单栏仍能恢复，用户无法从刚刚操作的位置解除穿透。定向向应用投递的自动化点击可能绕过系统命中规则，因此不能用这种点击成功反证用户反馈。

## Solution

根据用户最新要求，锁定且主窗口可见时保留原工具栏：锁图标高亮，其他图标置灰，不额外显示文字按钮。原锁图标上精确覆盖一个28 × 28 pt非激活命中面板，使用与原图标相同的绘制。该矩形是唯一鼠标命中例外，主面板继续保持穿透。点击按钮执行普通解锁；菜单栏“显示并解锁”继续作为独立恢复入口。

## User Stories

1. 作为用户，我希望锁定后仍有明确的就地取消入口，以便不用寻找其他菜单也能恢复操作。
2. 作为用户，我希望正文和按钮之外的区域继续穿透，以便锁定后仍可操作下层应用。
3. 作为用户，我希望普通解锁保留自动隐藏和透明度设置，以免一次取消动作重置我的配置。
4. 作为用户，我希望锁图标命中区域跟随窗口显隐，以免窗口隐藏后留下一个遮挡桌面的按钮。
5. 作为用户，我希望边缘唤醒锁定窗口时取消入口一并出现，以便随时解除穿透。
6. 作为用户，我希望收起、关闭或退出后不残留独立按钮，以免产生无法管理的孤立控件。
7. 作为用户，我希望120 × 90的小窗口也能完整显示取消入口，以免缩小后被锁住。
8. 作为用户，我希望菜单栏的“显示并解锁”仍保持原有恢复语义，以便就地入口不可见时仍能恢复。

## Implementation Decisions

### 唯一鼠标命中例外

| 项目 | 契约 |
| --- | --- |
| 显示条件 | 受管理主窗口存在、锁定且可见 |
| 承载方式 | 独立的 nonactivating child NSPanel；主面板仍保持 `ignoresMouseEvents = true` |
| 图标状态 | 锁图标蓝色高亮、其他图标置灰；悬停提示为取消穿透 |
| 尺寸 | 28 × 28 pt |
| 位置 | 与原锁图标完全重合，顶边距2pt，所有宽度下中心x=宽度−20 |
| 命中范围 | 仅按钮所在28 × 28 pt矩形接收鼠标；正文、其余工具栏和边框仍穿透 |
| 最小尺寸适配 | 在120 × 90和320 × 480下均位于主窗口内部，按钮不裁切，不额外增大主窗口最低尺寸 |

当前320×480窗口的锁图标命中区域为局部左上原点(286,2,28,28)；120×90时为(86,2,28,28)。紧凑窗口始终显示锁图标；锁定时其他图标置灰，解锁后恢复。

不通过鼠标悬停时暂时关闭主面板穿透来提供入口，也不让整个工具栏重新接收鼠标。按钮不能成为窗口拖动或缩放的入口；锁定时原有禁用移动、缩放的规则保留。

### 两种解锁命令

| 命令 | 状态变化 |
| --- | --- |
| 就地“取消穿透” | 执行普通解锁，仅将锁定设为关闭；保持主窗口frame、透明度、自动隐藏配置，不强制调用菜单栏恢复命令 |
| 菜单栏“显示并解锁” | 保持既有语义：显示主窗口、解除锁定、关闭自动隐藏，并清理原有采样历史和几何交互 |

Core状态机及普通解锁语义不变。本次修改位于原生窗口适配与命中路径，不新增Core内部测试，也不为子面板引入第二套锁定状态。

### 生命周期

| 主窗口或命令变化 | 子面板结果 |
| --- | --- |
| 未锁定 | 不显示、不参与命中 |
| 可见时开启锁定 | 附着到当前主面板并显示按钮 |
| 已锁定但主窗口隐藏 | 隐藏并解除父子附着关系，不保留可命中的按钮 |
| 已锁定窗口自动唤醒 | 重新附着到当前主面板并显示按钮 |
| 普通解锁或菜单栏恢复 | 移除就地取消入口；恢复后主窗口按对应命令操作 |
| 收起、关闭、退出 | 清理子面板及附着关系；关闭后不得留下孤立窗口 |

子面板不能独立延长已关闭主窗口的生命周期。重建窗口后只能使用新主窗口对应的入口；旧窗口的延迟操作不得解锁或重新显示新窗口。

使用非激活面板避免主动激活所属应用，但本实现选择不等于已证明所有焦点、全屏或Space行为。原M0的未验证项目继续保留。

## Testing Decisions

### 原生命中证据

对给定AppKit屏幕坐标，用 `NSWindow.windowNumber(at:belowWindowWithWindowNumber: 0)` 读取系统命中窗口，再通过 `CGWindowOwnerPID` 确定所有者。诊断命令为 `.build/verification/window-hit PID X Y owned|through`；`owned` 要求命中属于被测进程，`through` 要求未命中被测进程。它只读查询，不向目标应用投递鼠标事件。

修复前先用同一点的未锁定和锁定状态作正负对照；修复后在按钮内部与正文分别检查“属于自身”和“穿透”。还须核对属于自身的窗口确实是预期子面板，避免其他自有窗口遮挡造成假阳性。

命中查询证明当前坐标的系统目标，不直接证明按钮回调执行或下层应用收到了点击。按钮动作另用实际操作及公开状态观察核对。CUA定向点击可用于验证命令路径，但不能单独作为自然鼠标命中或穿透证据。

### 验收矩阵

| 标识 | 行为 | 证据要求 | 状态 |
| --- | --- | --- | --- |
| LR01 | 锁定且可见时，取消按钮矩形命中自身子面板；正文和其他区域仍穿透 | 系统命中窗口及owner PID的正负对照 | 修复前失败已复现；修复后320 × 480及120 × 90的所测点通过 |
| LR02 | 点击取消后解除锁定，frame、透明度、automaticHiding保持 | 按钮操作前后公开状态及子面板命中变化 | 两种尺寸下解除锁定、frame不变、可见性及auto false保持已验证；透明度未单独采集，auto true保持待补证 |
| LR03 | 锁定窗口隐藏时按钮隐藏并detach，唤醒后重新附着显示 | 主窗口/子面板可见性、附着关系和命中记录 | 待验证 |
| LR04 | 解锁、收起、关闭、退出均清理；关闭后无孤立按钮 | 操作后的窗口列表、附着关系及命中观察 | 解锁隐藏、解锁后关闭、重建及锁定状态退出已验证；收起、锁定直接关闭、自动隐藏detach待验证 |
| LR05 | 120 × 90和320 × 480均能完整显示并操作取消按钮 | 两种尺寸的原生布局与系统命中记录 | 两种尺寸命中及实际取消动作通过，最小尺寸布局完整 |
| LR06 | 菜单栏恢复仍显示、解锁、关闭自动隐藏 | 原生命令及公开状态观察，不混同普通解锁 | 待验证 |

已有Core测试可用于回归既有状态语义，但不能替代上述原生适配证据。构建、命中、按钮动作和生命周期结果分别记录，不因其中一项通过而扩展其他结论。

## Out of Scope

不重新设计其他工具栏按钮，不增加新的内容能力、全局鼠标监控或权限要求，不调整最小窗口尺寸，不扩展为全屏、多屏、Space或最低系统版本已通过的声明。本轮不补写与未变更Core实现耦合的内部测试。

## Further Notes

本规格对锁定穿透的例外是明确的28 × 28 pt交互区域，不是“全窗仍完全穿透”的实现细节。旧规格与验收记录涉及正文穿透时应按此范围理解；既有历史实测记录保留，不改写为修复后结果。
