# M0 任务计划：单窗锁定与边缘唤醒

状态：用户已确认计划；本表不记录实施成功，实际结果见[验收记录](../verification/m0-acceptance.md)。日期：2026-11-05。

后续范围更新：用户已要求窗口可拖动、边缘可缩放，详见 [Spec 003](../specs/003-move-resize.md)。本表保留初版 M0 任务历史；其中固定位置、无拖动缩放的限制已被该新规格覆盖。

行为依据：[Spec 001](../specs/001-single-window-behavior.md)。目标是验证一个固定网页窗的锁定、隐藏、边缘唤醒和菜单栏恢复闭环。后续用户指定的外观变更见 [Spec 002](../specs/002-reference-window-appearance.md)：默认 320 × 480 pt、参考图首页、工具栏，固定网页保留在调整菜单中。

2026-11-05 修订：依据用户关于卡顿、不灵敏和偶发漏触发的手动实测反馈，T07 补充相邻实际采样由外到内的唤醒规则及历史隔离；保留 30 ms 采样与 12 pt 热区。修复后用户确认慢速、快速唤醒均正常；焦点暂未测试，M0 其余待验收项见验收记录，不将本次唤醒复测通过记为 M0 完成。

## 执行规则

- T01 与 T02 可以并行，T03 依赖两者；其后按前一项依次推进。文档与环境准备可以并行，不并行编写同一行为的测试和实现。
- 自动化仅经已确认的控制器公开接口与 snapshot 验证行为。每次先运行一条失败测试，再写最小实现使其通过，最后审阅；不先写完全部测试，也不先写完全部实现。
- 将失败原因、通过结果和对应 AC 标识记录下来；不为基础工程脚手架编写只复述配置的测试。
- 真实窗口穿透、焦点和跨 Space 行为必须实测；控制器结果或窗口属性断言不能替代实际交互。
- 实机锁定与隐藏实验开始前，菜单栏的恢复、关闭和退出入口必须可用。

## 固定行为基线

- 同时最多一个窗口；初版尺寸 320 × 240 pt，后依用户参考图更新为 320 × 480 pt；初始可见、未锁定、未开启自动隐藏。M0 固定位置，无拖拽、缩放或热区宽度设置。
- 保持显示区是窗口外扩 12 pt 的闭合矩形；唤醒区是保持显示区减去窗口内缩 12 pt 后的严格内部。内外边界、角点均属于唤醒区。
- 保持 30 ms 采样。隐藏时直接命中热区可唤醒；若同一窗口的上一次有效实际采样在保持区外、本次在保持区内，则补发跨边缘唤醒，即使本次已在中央。
- 无历史的首次中央采样不唤醒；显示后中央保持显示。两次采样均在保持区外时不显示，即使线段穿过窗口；本规则不做完整轨迹插值。
- 开启自动隐藏时立即按当前位置决定显示或隐藏；关闭自动隐藏恢复显示、保留锁定。开关操作的当前指针不作为连续采样历史。普通锁定切换不改变可见性或自动隐藏状态。
- “显示并解锁”同时显示、解除锁定、关闭自动隐藏。关闭移除窗口；再次采样不会重新出现。重新创建是新的生命周期。
- 仅记录同一存活窗口、自动隐藏开启期间的实际采样；新窗口创建、关闭、恢复和自动隐藏切换清空历史，已有窗口时重复创建不重置历史。旧窗口 ID 或自动隐藏关闭时的采样不能影响当前状态或建立历史。
- 显隐不能重置配置中的透明度。自动唤醒不能激活 Oriel 或改变主应用键盘焦点。
- 浏览验收仅覆盖固定测试网页的普通链接、滚动和选文。表单、外部协议、新窗口链接、网络站点兼容性另开规格。

## 本次修订的执行顺序

先通过公开接口复现“隐藏且锁定，区域外实际采样后直接进入中央却未显示”，观察测试失败，再写最小修复。随后逐条覆盖首次中央、两端在外、旧窗口 ID 和历史清理规则；每条完成自己的测试与实现循环。

完成自动化与构建后，用实际指针重复验证用户报告的漏触发场景，并复核锁定穿透、恢复和自动唤醒焦点。结果写入验收记录；实机复测完成前保留唤醒稳定性未通过和 M0 未完成的结论。

## 完成门槛

AC01–AC09 的适用自动化与实机验收必须通过，AC11 的停止采样与退出行为必须验证；资源数值须附条件，不预设“开销可忽略”。

已执行的全屏或焦点验收不符合规格时，先修复方案或重新确定范围，不能记录现象后宣布通过。缺少硬件或系统版本的 AC12 项标记未验证，可继续独立开发，但不能宣称已支持全部多屏组合或已验证 macOS 14+。

CLT 构建通过与 Xcode 构建通过分开记录。M0 不包含签名、公证、发布、完整网页输入、多窗或持久化。
